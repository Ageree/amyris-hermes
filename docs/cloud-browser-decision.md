# Облачный браузер для мультитенанта — решение

**Дата:** 2026-06-26 · **Контекст:** Poke-для-РФ, мультитенант SaaS. Главный инструмент агента — браузер-автоматизация Yandex (`browser_order`), потому что в РФ нет consumer-API заказов. Нужно: держать **per-user залогиненную сессию** Yandex (с картой) между заказами, проходить мимо анти-бота (SmartCaptcha), масштабироваться на 100→1000 активных юзеров.

> Все цены/факты проверены **живьём** (curl/docs/web/exa) 2026-06-25…26 и прогнаны через adversarial-агентов (research → попытка опровергнуть каждое ценовое/прокси/persist-утверждение). Источник данных: workflow `wf_9fe918f0-eb2`, 23 агента.

---

## TL;DR

1. **Облачный браузер — это почти commodity-CDP-хост.** Реальный анти-детект под Yandex даёт **не** «нативный прокси провайдера», а **свой RU-мобильный/резидентный прокси**. Поэтому критерий №1 — провайдер должен принимать **BYO-прокси без тарифного гейта** + держать **persistent per-user профиль** + говорить по **CDP** (чтобы переиспользовать уже интегрированный `browser-use`).
2. **ПОБЕДИТЕЛЬ — `browser-use cloud`.** Это хостед-версия движка, который у нас **уже интегрирован** (browser-use/browser-harness, Python, CDP). Нулевая новая интеграция, самый дешёвый browser-compute ($0.02/час), BYO-прокси + RU в нативном enum, persistent-профили («login once, reuse»), `stealth` (форк Chromium + рандомизация fingerprint), и — главное — **`live_url`** (живой просмотр сессии) = готовый механизм **handoff для SMS/3DS/капчи**, которые агент не должен/не может пройти сам.
3. **РЕЗЕРВ — `Browserbase`** (зрелее, SOC2, лучшая persistence/security, нативный RU в списке + BYO с per-domain-роутингом). Второй резерв — **`Kernel`** (BYO без гейта, managed-прокси бесплатно, per-org шифрование профилей).
4. **Прокси (отдельный, не менее важный слой):** **`mobileproxy.space`** — выделенные RU-мобильные модемы (carrier CGNAT = высший trust у SmartCaptcha, рублёвый биллинг, постоянный sticky-IP) как ПУЛ, сайзенный под пиковую конкуренцию (НЕ один модем на юзера). Эластичный overflow — **`SOAX`/`IPRoyal`** (RU residential/mobile, sticky, крипто-биллинг). **Избегать: Bright Data / Oxylabs / Decodo** (Россия убрана из сети либо жёсткий KYC отклоняет RU-кейс).
5. **Модель на AI Gateway:** `minimax/minimax-m3` нативно, $0.30/$1.20 за M, keyless (OIDC). OpenRouter не нужен. (Деталь для спеки ядра.)

## Критерии (scored)

| # | Критерий | Почему важно для нашего кейса |
|---|----------|-------------------------------|
| 1 | **RF_PROXY** | Нативный RU-пул ИЛИ возможность вставить СВОЙ прокси (BYO). BYO без тарифного гейта = 4–5; нативный глубокий RU-пул = 5; только датацентр/нет прокси = 1–2. |
| 2 | **STEALTH** | Анти-детект/fingerprint + капча; пройдёт ли Yandex SmartCaptcha и **отрисует** ли 3DS/SMS-OTP (нам нужно показать их юзеру, не «взломать» оплату). |
| 3 | **PERSIST** | Per-user профиль: cookies/localStorage логина живут между заказами (contexts/profiles/user-data-dir). |
| 4 | **CDP** | CDP/Playwright-совместимость → переиспользуем уже готовый `browser-use`/`browser-harness` с минимумом правок. |
| 5 | **SECURITY** | Как хранятся залогиненные, привязанные-к-карте сессии (шифрование at-rest, изоляция тенантов, SOC2, регион). |

**Модель стоимости на масштабе** (для оценки 100/1000): «активный юзер» ≈ 3 заказа/день × ~4 мин = ~12 browser-мин/день = ~360 мин/мес; ~6 ГБ трафика/юзер/мес через прокси. Месячная цена = (browser-минуты × ставка) + (ГБ × цена прокси) + тарифный сбор.

> **Ключевая поправка к экономике:** прокси **не нужен 1:1 на юзера**. Логин живёт в **профиле браузера** (cookies), а не в IP — IP должен лишь быть RU-доверенным. Значит нужен **ПУЛ RU-выходов, сайзенный под пиковую конкуренцию** (sticky на время одного заказа), а не на общее число юзеров. Это радикально удешевляет масштаб (см. ниже).

## Почему победитель — `browser-use cloud` (а не формальный лидер Anchor 23)

Anchor набрал 23, но **BYO-прокси у него только на тарифе Growth $2000/мес** — а BYO-прокси для нас обязателен (см. ниже про RU-прокси). Платить $2000/мес ради «вставить свой прокси» на стадии 100 юзеров — нерационально. Bright Data набрал 21 с реальным нативным RU, но **эфемерные 30-мин сессии** убивают главное требование — держать логин между заказами.

`browser-use cloud` выигрывает практикой, а не формальным баллом:

1. **Нулевая новая интеграция (ponytail).** Проект **уже** гоняет `browser-use`/`browser-harness` (Python, CDP, Lane B — см. `browser-harness-fleet-integration`). browser-use cloud — это та же связка, только Chrome живёт в облаке. Миграция = заменить `BU_CDP_URL=http://127.0.0.1:9222` (локальный Chrome в GCP-контейнере) на облачный CDP-эндпоинт + `profile_id` на юзера + BYO RU-прокси. Драйвер не переписываем.
2. **Самый дешёвый browser-compute:** $0.02/час против $0.05–0.48 у конкурентов.
3. **BYO-прокси без гейта** (`custom_proxy` HTTP/SOCKS5 + `proxyCountryCode`) + RU есть в нативном enum (как запасной выход).
4. **Persistent-профили** («login once, reuse across sessions», `profile_id`, `keep_alive`).
5. **`live_url`** — встроенный живой просмотр сессии. Это готовый **handoff-механизм**: когда всплывает SMS-код/3DS/капча, которую агент не должен проходить сам, мы кидаем юзеру `live_url` — он жмёт/вводит сам в той же сессии. Уникально полезно для РФ-флоу.
6. **Stealth** лучший из API-first-набора: форк Chromium, рандомизация fingerprint (canvas/webgl/fonts/navigator), обход Cloudflare/PerimeterX.

**Слабое место (честно):** `security` = 3 — изоляция/шифрование per-user карт-сессий в публичных доках не подтверждена; задокументированная ставка BYO-egress отсутствует (подтверждён только нативный $5/ГБ). → **Before-lock-проверка:** запросить у browser-use изоляцию/шифрование профилей + ставку BYO-egress. Если security не устроит — переключаемся на **Browserbase** (SOC2, dedicated-VM, contexts с шифрованием) тем же CDP-кодом.

**Резерв:** `Browserbase` (security/зрелость) → `Kernel` (бесплатный managed-прокси + per-org шифрование). Все три — CDP, так что переключение между ними — это смена URL/SDK, не переписывание тула.

## Прокси под РФ — отдельное (и не менее важное) решение

> Это **главный анти-детект-рычаг**, не облачный браузер. Вывод research: RU-**residential** и особенно RU-**мобильный** IP материально снижают частоту SmartCaptcha против датацентра, но **не** убирают полностью (SmartCaptcha также смотрит TLS/JA3, fingerprint, поведенческий ритм → IP **необходим, но не достаточен**; нужны реалистичный fingerprint + человеческий темп). **Carrier-мобильный** — высший trust (тысячи реальных абонентов за одним CGNAT-IP, Yandex не может его заблокировать). **Sticky обязателен:** держать ОДИН доверенный IP на весь флоу login→cart→checkout — смена IP сама триггерит капчу.

| Вендор | RU-пул | Цена | Sticky | Биллинг из РФ | Вердикт |
|--------|:------:|------|--------|---------------|---------|
| **mobileproxy.space** (RU-local) ⭐ | ✅ выделенные RU 4G-модемы (МТС/Билайн/Мегафон/Tele2/Yota) | ~$25–50/мес за модем (flat, безлимит) | ✅ постоянный (один IP держится сколько нужно) | ✅ рубли/SBP/YooMoney, **0 санкц.-трения** | **PRIMARY.** Высший SmartCaptcha-trust, постоянный sticky под весь заказ. |
| **SOAX** | ✅ ~2M RU residential+mobile, city-targeting | $0.32–3.60/ГБ | ✅ переживает обрыв | Лёгкий KYC, крипто | **SCALE/overflow.** Глубочайший western RU-пул. |

**Архитектура прокси:** на старте — небольшой **пул выделенных RU-мобильных модемов** (`mobileproxy.space`), sticky-назначение модема на время одного заказа, размер пула ≈ пиковая конкуренция (НЕ число юзеров). Эластичный overflow — SOAX/IPRoyal residential per-GB. Биллинг-тактика: western-вендорам платить криптой (обход карт-санкций), RU-локальным — рублями/SBP.

## Экономика на масштабе (победитель: browser-use cloud + пул RU-мобильных модемов)

Пул модемов сайзится под **пиковую конкуренцию**, а не под число юзеров (логин в профиле, не в IP):

| | browser-compute | RU-прокси (модем-пул) | план | **Итого/мес** | На юзера |
|---|---|---|---|---|---|
| **100 юзеров** | ~$12 (360мин×100×$0.02/час) | ~10–20 модемов ≈ $250–1000 | $29–299 | **~$300–1 300** | ~$3–13 |
| **1000 юзеров** | ~$120 | ~50–100 модемов ≈ $1 250–5 000 | $299–999 | **~$1 700–6 100** | ~$1.7–6 |

Для сравнения — если брать **нативный residential per-GB** (SOAX/IPRoyal, проще стартовать, дороже на масштабе): 100 юзеров ≈ $1 200–2 200/мес, 1000 ≈ $10 600–18 000/мес. → **Модем-пул дешевле И выше trust на масштабе**; per-GB residential — как эластичный overflow.

> Для контраста: «всё нативное» на Browserbase ($10/ГБ managed-прокси) выходит **~$6 060/мес (100)** и **~$60 600/мес (1000)** — на порядок дороже, потому что нативный managed-прокси у cloud-браузеров дорогой и под РФ всё равно неглубокий. Отсюда и вывод: **BYO RU-прокси — не опция, а основа экономики.**

## Рассмотрено и отклонено

- **Anti-detect-браузеры с облачными профилями** (GoLogin [RU-основан], Octo Browser [RU], Dolphin Anty [RU/CIS], AdsPower, Multilogin, Kameleo): сильны RU-нативными persistent-профилями + CDP, НО это инструменты для **ручных мульти-аккаунт-ферм**, а не serverless API под автономного мультитенант-агента. Менее API-first, больше ручного оркестрирования. Держим как запасной паттерн, если cloud-API-путь не вытянет stealth.
- **Kasm Workspaces** (self-host container-streaming на RU-VPS = нативный RU-egress): лучший «собери сам / self-host в РФ» вариант. Отклонён сейчас как тяжёлый build; держим как путь, если нужен полный контроль/хостинг внутри РФ.
- **Notte / Scrapeless / Airtop / Nstbrowser**: годные CDP+профили+прокси, но новее/менее проверены и не дают reuse-преимущества browser-use cloud.

## Что проверить перед финальным lock (before-lock)

1. **browser-use cloud security:** изоляция и шифрование per-user профилей (карт-сессии!) + регион хранения + ставка **BYO-egress** (в доках только нативный $5/ГБ). Если не устроит → Browserbase тем же CDP-кодом.
2. **RU-выход живьём:** прогнать `mobileproxy.space` модем → Yandex login → SmartCaptcha-частота на throwaway-аккаунте (НИКОГДА на личном). Подтвердить, что carrier-mobile реально снижает капчу в нашем флоу.
3. **CDP-связка:** browser-use cloud CDP-эндпоинт + BYO `custom_proxy` (RU-модем) + `profile_id` → переиспользовать существующий `browser-harness`-драйвер (сменить только `BU_CDP_URL`).

---

## Решение

- **Облачный браузер: `browser-use cloud`** (победитель — reuse + цена + `live_url`-handoff). **Резерв: `Browserbase`** → `Kernel`.
- **Прокси: `mobileproxy.space`** (RU-мобильные модемы, пул под конкуренцию) **PRIMARY**; **`SOAX`/`IPRoyal`** — эластичный overflow. **Избегать Bright Data/Oxylabs/Decodo.**
- **Браузер ≠ анти-детект.** Анти-детект = RU-мобильный прокси + реалистичный fingerprint + человеческий темп + sticky на весь заказ. Облачный браузер — сменяемый CDP-хост.

→ Этот выбор зашит в секцию `browser_order` спеки ядра (`docs/eve-core-spec.md`).
